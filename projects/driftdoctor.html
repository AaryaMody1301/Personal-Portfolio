The problem

A renamed field, changed model reference, or duplicate record can break a pipeline. A successful build alone does not prove the business contract still holds. I wanted repairs to carry their reasoning and verification with them.

The first simple-agent baseline resolved 0 of 12 frozen cases. Free-form generation could produce a confident explanation without a correct patch. That failure shaped the final architecture.

The approach

  1. Copy into a disposable sandbox. Work on a local DuckDB-backed dbt project, preserving the original source.
  2. Apply deterministic skills. Route contract-defined changes to inspectable transformations for aliases, casts, grain, references, and documented formulas.
  3. Use AI only for supported ambiguity. Select an existing observed candidate or abstain. The model cannot invent a model or rewrite arbitrary SQL.
  4. Verify and return evidence. Run dbt and contract checks, then produce a reviewable diff and driftdoctor-report.json. A reviewer must approve the result.

A separate ambiguity demonstration

The held-out stg_orders case offered two existing model candidates. Skills alone escalated. The bounded agent selected stg_orders_v2 in one model call and passed the held-out checks. This demonstration is reported separately from the twelve-case score.

Decisions & limits

The useful improvement was narrowing the model’s job. Explicit skills handle work determined by the contract; the agent makes only one supported ambiguity decision.

The benchmark is synthetic and small. The current scope is local DuckDB dbt projects, explicit repair skills, and one bounded ambiguity pattern. Novel SQL structures and undocumented rules should escalate. Broader independent holdout evaluation is needed before production use.
