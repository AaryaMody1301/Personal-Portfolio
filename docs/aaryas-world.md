# Aarya’s World

The portfolio is a static HTML document enhanced with a locally bundled Three.js scene and GSAP transitions. `index.html` owns all project stories, job facts, qualifications and contact destinations. Panels move those existing elements into a native dialog and restore them on dismissal; they do not maintain a second content collection.

## Views and navigation

The homepage `/` is a compact reading layout: actual current role, analytics/engineering capabilities, selected work, resume and contact. It requests no World bundle, poster, GLB or environment. The search layout is reserved before enhancement loads to avoid shifting cards; without JavaScript it stays absent. `?view=read` remains supported. Explore world enters `?view=world`; only then are World assets requested and the poster revealed while the scene initializes. Explicit World/legacy-island visits preload only the matching poster, render it before 3D compilation, and recover the reading document if the main bundle fails. Bare `#island-*` links retain legacy World travel. Ordinary section/project anchors default to reading. Reduced motion, missing WebGL or renderer failure maps island destinations to the relevant reading story.

Desktop navigation covers Work, About, Experience, Contact, Resume and the mode switch. Below 960px, a native expandable menu has readable 44px targets. Reading section highlights follow scroll position. Search covers all fourteen project titles, descriptions and technologies; Engineering, Analytics and AI/Applications filters, counts, empty state and reset use memory only. Direct links reveal filtered projects. Four selected stories lead: DriftDoctor, SQL Practice Project, Sales Forecasting, Video Game Sales Dashboard.

`index.html` owns the project collection. Cards and reading content use native disclosures; World panels move the same elements into a native dialog and restore them on dismissal. The fixed panel header and footer enclose a separate scrolling body. A 44px close button centers its 20px block SVG. The panel title receives initial focus; native focus trapping, Escape and invoking-control restoration remain. Copy email/project link provides accessible feedback and a selectable-text fallback on clipboard denial.

World keeps destination labels with prominent project names, a current-destination indicator, compact help, orbit/reset and the three illustrative demonstrations. Introductory copy is hidden/inert while a panel is open. Closing it preserves the camera. Mode changes create history entries; Back/Forward restores view, destination and reading position. Camera/sample state survives reading, hidden resizing and repeated mode switches. Zero-size layout measurements are ignored; dimensions refresh before rendering resumes. Hidden tabs and reading suspend rendering. Permanent page departure disposes the renderer and explicitly releases its GPU context; cached Back/Forward pages pause and resume it. Short landscape layouts hide the extra status copy so it cannot overlap the primary action. JavaScript disabled leaves the reading document and disclosures usable.

## Sources and build

Edit `src/main.mjs`, `src/world.mjs`, `assets/css/world.css`, and the HTML content. Run `npm run build` after changes. esbuild bundles only local dependencies; no CDN is used at runtime. The generated `assets/css/style.css`, bundles, their legal notices, immutable hash copies and HTML references belong in the same release.

`scripts/prepare-assets.mjs` hashes leaf resources first, rewrites the stylesheet’s font URL, then hashes parent resources. `assets/manifest.json` records every runtime resource, including the lazy models, environment map, fonts and posters. `npm run assets:check` verifies all generated bytes and references. Deployment verification compares transitive assets, the manifest, legal notices and the original resume with the target server.

All imported notices are in `assets/licenses/THIRD-PARTY-NOTICES.txt`, linked visibly in Credits. Dimension’s panel composition is adapted under CC BY 3.0; Kinetic’s expanding grid retains its TemplateMo credit; the raised button is adapted from Uiverse’s MIT source. The simplified archive shader is adapted from Jatin Chopra’s MIT Codrops demo. Three.js, GSAP, Lucide and Syne retain their notices.

The scenery uses Quaternius’s CC0 `BirchTree_1` and `Bush_Small` geometry, converted to self-contained GLB files. The public foliage texture downloads hit Google Drive’s quota, so the small leaf silhouette is original. Island foundations, rocks and machines are original geometry. Poly Haven’s CC0 Venice Sunset lights the higher-quality scene. Its CubeUV HDR is filtered ahead of time with Three.js PMREM, avoiding visitor-side GPU convolution; `npm run assets:environment` can regenerate it from the retained 1k source. Normal builds need no browser or ignored asset inputs. The final lighting loads before shader preparation, and hidden buffer-upload frames retain all scene lights to avoid creating new shader variants. Mobile uses the matching palette, simpler Lambert materials and built-in directional lighting. Low quality also removes particles, reduces vegetation, caps pixel density and renders at about 30 fps; desktop caps density at 1.5 and rendering at about 40 fps.

## Verification and delivery

Use `npm run check`, `npm run test:release`, `npm run test:ci`, and `npm run audit:preview`. Tests cover navigation, samples, keyboard access, focus, direct links/history, reduced motion, no JavaScript, asset failure, WebGL failure/context loss and responsive layouts. Lighthouse gates remain 90 Performance and 95 Accessibility, Best Practices and SEO.

`npm run preview:capture` records review screenshots. To explicitly regenerate scene posters and the 1200×630 social card, use `npm run preview:capture -- --refresh-assets` against localhost, then rebuild. `npm run compatibility:capture` records the existing Chrome, Firefox and WebKit profiles. `npm run profile:world` measures twelve seconds of active scene interactions separately from Lighthouse and records the actual host/browser and emulated devices.

`npm run package:hostinger` produces `output/portfolio-hostinger.zip` and checks every packaged file against its source, including the unchanged resume. Publishing is a separate release action. The dated results and testing limits are recorded in [the current verification report](aaryas-world-verification.md).
